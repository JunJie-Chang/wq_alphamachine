# 新手指南:WorldQuant BRAIN 平台 + alphamachine 專案運作說明

寫給還不熟 BRAIN 平台的你。分兩大部分:**Part 1** 從零介紹平台規則,**Part 2**
說明 `alphamachine`(這個專案)實際上是怎麼運作的。文末附即時戰績快照。

如果哪個數字看起來眼熟又怪怪的 —— 網路上流傳的很多 threshold 其實是
**User 層級的 WorldQuant Challenge** 數字,不是 **Consultant 層級**規則,
兩者系統性不同。這份文件跟 `docs/BRAIN_RULES.md` 一樣,只採信官方文件與
平台實查結果,不採信網路二手資訊。

## Part 1 — WorldQuant BRAIN 平台入門

### 1.1 這整套系統在幹嘛

WorldQuant 是一家對沖基金。BRAIN 是他們開放給外部研究者(叫 **Consultant**,
顧問)的一個線上模擬平台:你寫一段數學公式(叫 **alpha**),平台用歷史股票
資料幫你回測,算出這段公式如果拿去交易會有多賺錢、多穩定。如果這段公式
夠好、又跟平台已經收錄的東西夠不一樣,你就可以把它**提交**進 WorldQuant
的正式基金組合,之後每一季會依照它的表現分錢給你。

一句話:**你不用自己的錢交易,你只需要想出「好的交易訊號」,平台幫你驗證
跟執行,分潤給你。**

### 1.2 什麼是 alpha

一個 alpha 就是一段公式,輸入是股票的各種資料欄位,輸出是「今天每支股票要
買多還是賣多」的權重。舉個真實例子(這個 session 送出去、目前狀態
`ACTIVE` 的那支):

```
group_neutralize(rank(ts_delta(ts_backfill(eur_director_value_2, 120), 66)), industry)
```

拆解讀法:
- `eur_director_value_2` —— 一個原始資料欄位(董事會相關的數值)
- `ts_backfill(..., 120)` —— 這個欄位常常缺值,用過去 120 天的資料補齊缺口
- `ts_delta(..., 66)` —— 算「跟 66 天前比,變化了多少」(不是看絕對水位,是看趨勢)
- `rank(...)` —— 把所有股票依這個變化量排序,排序本身就是要買/賣的權重
- `group_neutralize(..., industry)` —— 把每個產業內部的多空互相抵銷,避免這支
  alpha 其實只是在賭「某個產業整體漲或跌」

平台每天用這條公式重新計算一次權重,理論上就照著買賣。

### 1.3 怎麼算錢

**Fitness** 是平台的核心品質分數:

```
Fitness = Sharpe × √( |Returns| / max(Turnover, 0.125) )
```

`max(·, 0.125)` 這個夾子很關鍵:**turnover(換手率)低於 12.5% 之後,再降
低也不會多拿到 fitness**。很多新手把 alpha 過度平滑到 3-5% 換手率,其實是
在犧牲真實報酬去換一個根本不存在的 fitness 加分。

實際分錢分三層,由粗到細:

1. **Base Payment**(基礎給付)—— 只算你**每天前 4 支 alpha + 1 支
   SuperAlpha**,乘上一個 Quality Factor。網路上常聽到的「一天 2,000 分」
   是 User 層級 Challenge 的東西,顧問制度沒有這個上限,但也不是送越多
   越好(只有前 4 支被算)。
2. **Dynamic Pyramid Multiplier**(動態金字塔乘數,1.0~2.0)—— 疊加在
   Quality Factor 上。**Pyramid** 的定義是 `地區 × 延遲天數 × 資料類別`,
   例如 `USA/D1/ANALYST`。**哪個 pyramid 的資料在全平台用得越少,乘數就
   越高**,每天可能變動。如果你的 alpha 同時碰到好幾個 pyramid 的資料,
   拿到的是**其中最低的那個**乘數 —— 意思是,把太多不同類型的資料混進
   同一條公式,反而可能拉低你的乘數。
3. **季度給付**(Quarterly Payment)—— 這個才是大錢,而且有一個容易忽略的
   門檻:**近 3 個月內提交天數少於 20 天,Value Factor 會被打到最低**。
   重點是「提交的天數」不是「提交的數量」——**每天提交 1-4 支、天天提交**,
   比「攢一批一次丟出去」划算得多。

還有兩個違反直覺、值得記住的事實:**universe 選越大越好**(TOP3000 比
TOP200 對顧問更有利,跟 User Challenge 的邏輯相反),以及 **D0 跟 D1 從
2023 年後給付已經一樣**,不用為了搶 delay 硬調整策略。

### 1.4 送出前要過的關卡(submission checks)

這是最容易踩雷的地方。平台會在你的 alpha 上跑一整組檢查,**任何一項沒過,
提交就會被拒**,而提交名額是有限的、被拒也算用掉一次機會。Consultant D1
(非中國區)的實際門檻:

| 檢查 | 門檻 | 白話意思 |
|---|---|---|
| `LOW_SHARPE` | Sharpe > **1.58** | 報酬穩不穩定 —— **這才是顧問的真門檻**,網路最常見的「1.25」是 User Challenge 的數字,拿來當顧問門檻會白白送出必死的 alpha |
| `LOW_FITNESS` | Fitness > 1.0 | 見上面公式 |
| `LOW_TURNOVER` / `HIGH_TURNOVER` | 0.01 ~ 0.70 | 換手率不能太低(代表沒在動)也不能太高(交易成本會吃掉獲利) |
| `MAX_STOCK_WEIGHT` | < 0.10 | 不能把全部身家壓在一兩支股票上 |
| `SELF_CORRELATION` | < 0.70 | 跟**你自己**已經提交過的其他 alpha 不能太像 |
| `PROD_CORRELATION` | < 0.70 | 跟**全平台所有人**已經提交的 alpha 不能太像 —— 這是目前這個專案卡最久的一關,下面會細講 |
| `LOW_2Y_SHARPE` | 通常 ≥ 1.58(每支 alpha 各自算,實測看過 2.02) | 近兩年還有沒有在賺 —— 防止一支「五年前很神、後來死掉」的訊號矇混過關 |
| `LOW_SUB_UNIVERSE_SHARPE` | 公式算出的門檻,不是固定值 | 换到更小的股票池(比如剔除最不流動的那批)還要保有多少 Sharpe,防止「其實只是流動性小的雜訊」 |

還有一些是純過/不過、沒有數值的:`CONCENTRATED_WEIGHT`(權重集中度)、
`IS_LADDER_SHARPE`(依你用了幾年的歷史資料,門檻不同)、
`MATCHES_COMPETITION`。

**這些門檻不是「猜的」——每一次模擬回來的結果裡,平台會直接把每一項檢查的
數值、門檻、通過與否都告訴你**,只是大部分人沒去讀它。

### 1.5 Genius 等級制度

這是一個每季重新評定的分級,直接影響你「能做什麼」跟「多久要驗證一次身分」:

| | Gold(新手預設) | Expert | Master | Grand Master |
|---|---|---|---|---|
| 資料欄位存取 | 50% | 61% | 78% | 100% |
| Operator 存取 | 45% | 63% | 78% | 100% |
| **生物辨識驗證間隔** | **4 小時** | 6 小時 | 12 小時 | **24 小時** |
| 季度給付量級 | — | — | $2,000+ | $8,000+ |

升等需要同時滿足三個門檻(2026 Q3 實際數字):**每季提交的 signal 數量**
(Expert 20 / Master 120 / Grand Master 220)、**完成的 pyramid 數量**
(Expert 10 / Master 30 / GM 60,一個 pyramid 要在裡面提交滿 3 支 alpha
才算「完成」)、以及一個叫 Combined Alpha Performance 的門檻(目前平台上
沒公布具體數字)。

這件事不只是為了賺更多錢 —— **Gold 等級 4 小時就要重新做一次臉部驗證**,
這個 session 已經因為這個間隔太短,好幾次卡住整條 pipeline 好幾個小時。
升等到 Grand Master 可以把這個拉到 24 小時,是真金白銀的營運成本,不只是
虛榮數字。

### 1.6 生物辨識驗證與配額

平台每隔一段時間會要求你做一次瀏覽器裡的人臉辨識確認身分(不是每次登入都
要,是 session 過期時)。有兩個容易踩的坑:

- **這個驗證請求(inquiry)綁定在發起它的那個 session 上**,不是綁定在你
  的帳號 —— 換一個 session 去完成別的 session 生出來的連結,會無限卡住。
- **完成驗證的那一步(finalize)本身就是登入了**,不需要再重新打一次
  登入 API —— 重打反而會生出一個新的 inquiry,浪費配額。

**平台硬性上限是一天 25 次**,超過會被鎖(`BIOMETRICS_THROTTLED`,鎖住後
沒有明確的解鎖時間,比單純等配額回補更痛)。這個專案自己設了更保守的
**20 次/24 小時**防線,寧可少用一點也不要撞到平台的鎖。

### 1.7 常見迷思澄清

- ❌「顧問 Sharpe 門檻是 1.25」→ ✅ 那是 User Challenge 的數字,顧問 D1 是
  **1.58**
- ❌「一天最多 2,000 分」→ ✅ 那也是 User Challenge 概念,顧問制度是「每天
  前 4 支 + 1 SuperAlpha 算錢」,沒有分數上限這回事
- ❌「universe 選小一點(TOP200)比較精準、比較好」→ ✅ 對顧問來說**越大
  的 universe 越有利**
- ❌「D0(當天執行)比 D1(延遲一天)好」→ ✅ 2023 年後給付已經一樣

## Part 2 — alphamachine 這個專案怎麼運作

### 2.1 一句話定位

多數公開流傳的 BRAIN 挖礦腳本是「暴力網格搜尋」:欄位 × 樣板 × 參數全部
組合硬跑一遍,跑完照 Sharpe 排序。alphamachine 不這樣做——底下不用規則
表,直接跟著**一個候選從出生到活下來(或死掉)** 走一遍,你會看到它每一
步實際在幹嘛、為什麼那樣決定。

### 2.2 跟著一個候選走一遍:機器現在正在做的事

**每一輪開始前,機器先回頭看自己的紀錄。** 過去每一種「題材 × 轉換手法」
的組合(例如「分析師預估欄位 × 找轉折點的公式」),粗篩活下來的機率、活
下來以後真的能送出去的機率各是多少,全部記在資料庫裡。機器用這些歷史數字
做一次抽籤(Thompson sampling)——不是均分預算,是機率高的組合這一輪拿
到更多嘗試次數,機率低的被冷落。**從沒試過的新組合不會被當成零**——先用
一個 AI 讀過欄位說明產生的粗略猜測墊底,再讓真實結果慢慢蓋過去。

**分配到預算的每一格,機器接著要決定「具體寫哪一條公式」。** 從那個題材
底下的所有欄位裡,依「冷門程度 × 這個欄位現在的 Pyramid 乘數」加權抽一個
——刻意偏好還沒被挖過、而且現在比較好賺的欄位。時間窗跟分組方式隨機挑一
組。如果這個欄位常常缺值,就先把公式包一層「用過去 120 天補值」,不然缺
值會讓後面的排序、變化量全部失真。寫好之後先檢查語法合不合法——**不合法
直接丟掉,連一次模擬額度都不浪費**,因為平台是「先收費才幫你解析」,語法
錯在這邊抓比在平台那邊抓便宜太多。

**準備好的候選,湊滿 10 支一批送出去模擬。** 3 個模擬名額,一次可以掛
10 支一批,等於同時有 30 支在跑。送出去的那一刻,先把「這批東西已經送出
去了」寫進資料庫,才開始等結果——這樣就算程式這時候當掉,重開之後也知道
不用重付一次錢。

**結果一支一支回來,全部先記下來。** 只有 |Sharpe| 超過 0.65 的才有資格
往下走(這個門檻刻意設得低——曾經真正跑出來的贏家,粗篩時只有 0.94,是
補值之後才顯出真本事的,設高了會提早殺掉真正的訊號)。沒過的不會被丟掉,
只是先擱在那邊,不再花力氣。

**活下來的挑分數最高的一批,一支一支開始精修。** 這是整個機器裡最像「思
考」的一段——每一步都先讀「現在卡在哪個檢查」,再決定調哪個參數:

- 先看正負號。Sharpe 是負的,直接整條公式加個負號反過來——一支 −1.6 就
  是一支被寫反的 1.6,不用重挖。
- 換中性化方式(把某種系統性偏誤——例如整個產業一起漲一起跌——從公式裡
  拿掉的技術)。這是唯一固定「全部都試一遍」的一步,9 種方式各跑一次,因
  為過去發現這是影響最大的單一槓桿。**以前,這一步選誰當贏家只看哪個
  Sharpe 最高**;**這是今天剛接上去的東西**:現在也會一起考慮「這種中性
  化方式,歷史上真的通過最後那道 `PROD_CORRELATION` 審核的機率有多高」——
  不是不看 Sharpe 了,是兩件事一起權衡,而且刻意讓這個歷史機率的影響力小
  於「差一項檢查沒過」的扣分,不會讓它蓋掉真正的品質差異。改完之後幾個
  小時,新選出來的贏家裡「歷史上比較容易過關」的中性化比例,從 17% 跳到
  56%(細節見 Part 3)。
- 檢查有沒有缺值、極端值、權重過度集中的症狀,有才處理,沒有就跳過。
- 算一下現在的換手率離 12.5% 那個「多換手也不會多加分」的甜蜜點還有多
  遠,朝那邊調整——不是亂試,是算出目標值再提候選。
- 掃一遍幾個固定的權重上限選項,全部試過(選項只有 4 個,便宜到不用挑)。
- 換到一個更小的股票池上再測一次,看這支 alpha 會不會死掉——這不是在優
  化,是在驗屍:如果只在最大的股票池裡活得下去,很可能只是靠流動性小的
  雜訊撐起來的假訊號。
- 六步都走完,最後留下來的那個版本標記成「精修完成」,代表這條公式目前
  能做到的最好版本已經找出來了。

**精修完成不等於可以送。** 還要再過兩關,而且刻意分成免費跟花錢兩段:

先做**完全免費**的檢查——Sharpe、Fitness、換手率、drawdown、多空平衡、
近兩年還有沒有在賺——這些數字模擬跑完就自帶了,不用再問平台一次,所以先
篩一輪不用等。過了才捨得問平台一次**真正花配額**的問題:「這支跟你已經
送出去的東西、跟全平台所有人送出去的東西,像不像?」這是整條流程裡最貴
的一步,所以留到最後、只對已經確定夠好的候選才問,而且每次都問現場結
果,不信舊的快取——因為這個答案會隨全平台的 book 隨時變動。

**過了兩關的候選,不是全部都送。** 從裡面挑一個「彼此夠不一樣」的組合:
先選分數最高的一支,接下來每一輪都選「扣掉跟已經選進來的東西有多像之後,
剩餘價值還是最高」的那一支——比較相似度用的是**每天的報酬變化**,不是
累積報酬(兩支完全無關的 alpha,累積報酬曲線畫出來也會長得很像,這是最
容易誤判的地方)。這樣選出來的組合,才會是「一堆彼此不重複的想法」而不是
「同一個想法的十個變體」。

**最後這批名單,預設狀態是「假裝送出去看看結果」,不會真的動作。** 要人
明確下指令加上 `--live` 才會真的送。而且就算前面每一關都過了,送出前還
會再問平台**最後一次**現場結果——不信任何快取。送出去之後,還會回頭重新
讀一次這支 alpha 現在的狀態,**確認它真的變成 `ACTIVE`**——因為平台回應
「收到了」不代表真的成功,可能事後判定相關性太高又悄悄退回去。

**這整套流程包在一個無限迴圈裡自己跑。** 唯一會讓它停下來的,是平台要求
重新做一次臉部驗證——機器自己做不到這件事,只會留一個訊號在那邊,等人來
處理,處理完會**自動接回剛剛卡住的那一步繼續**,已經做完的部分不會重算、
不會重付錢。

**跑完的每一個結果,都會回頭改變下一輪的決定。** 哪個題材 × 轉換手法真
的換到分、哪種中性化真的通過稽核、拿到多少 Pyramid 付錢乘數——這些全部
被記下來,餵回最開頭「這一輪預算要灑在哪」跟中間「精修時選誰當贏家」的
判斷裡。機器現在的行為,是被它自己過去所有結果形塑出來的,不是一套寫死
不會變的規則。

### 2.3 現在卡在哪、下一步

**目前唯一沒鬆動的牆是 `PROD_CORRELATION`**:量測過的 600 多支裡,只有約
20 支低於 0.70 門檻,而且全部都來自剛才提到的那幾種非典型中性化。這不是
調參數能解的,是「這個題材本身在全平台已經很擁擠」的結構性問題。

還沒做、值得考慮的方向:
- **Genius 等級進度追蹤**——目前只有 1 支已提交、1 個 pyramid 被碰過,離
  Expert 等級需要的「10 個 pyramid 各滿 3 支」還很遠,但這件事會直接縮短
  4 小時的驗證間隔,是省時間的槓桿。
- Osmosis 配點、Power Pool 資格——這個專案目前完全沒碰,`docs/` 裡有現成
  的規則文件,還沒被讀進程式碼裡評分。
